# Agent Replay Backtest Result Links Design

## Purpose

Agent Workflow Replay explains how agents reasoned and which tools/orders they used, but it does not directly answer how the selected backtest performed. Add backtest-level result links so a developer can jump from an agent run to account performance artifacts.

## Goals

- Add two buttons to the Agent Replay workflow header:
  - `Account Curve`
  - `Performance Report`
- Bind the buttons to the selected strategy + backtest run, not to the selected system run/day.
- Enable `Account Curve` when the backtest artifact root has `stats.csv`.
- Enable `Performance Report` when the artifact root has an HTML report such as `*_tearsheet.html`.
- Disable buttons with a readable reason when artifacts are missing.
- Open result pages in a new browser tab.

## Non-Goals

- Do not change how backtests are generated.
- Do not require every run to have a tearsheet.
- Do not build a full analytics dashboard in this pass.
- Do not modify the agent trace schema.

## Design

The replay loader already receives trace roots such as:

```text
.../growth-execution-test/cache/agent_runtime
```

The corresponding backtest artifact root is:

```text
.../growth-execution-test
```

For each `ReplayRun`, the loader should include an `artifacts` object:

```json
{
  "account_curve": {
    "available": true,
    "url": "/artifacts/<token>/account-curve",
    "reason": null
  },
  "performance_report": {
    "available": false,
    "url": null,
    "reason": "No tearsheet HTML found for this backtest run."
  }
}
```

The token should be opaque and generated by the Flask server from configured trace roots. It must not expose arbitrary filesystem access. The server should only serve artifacts under the configured backtest artifact roots.

## Account Curve Page

The first version can be a lightweight HTML page generated by the server. It should read:

- `stats.csv`
- optionally `result.json`

It should show:

- backtest artifact path label
- key summary metrics from `result.json` when available
- a compact table or simple SVG/polyline for `portfolio_value` and `cash`

This page is intentionally simpler than a full performance dashboard.

## Performance Report

The server should search the backtest artifact root for likely report HTML files in this order:

1. `*_tearsheet.html`
2. `*tearsheet*.html`
3. `*_stats.html`
4. any `.html` file containing `tearsheet` or `report` in the name

If found, the button opens the HTML file through a safe read-only server route. If not found, the button is disabled.

## UI Behavior

- Buttons live in the top workflow header next to `System Overview` / `Hide Graph`.
- Button state updates when the selected backtest run changes.
- Disabled buttons use `disabled` and `title` text for the missing reason.
- Open enabled buttons with `target="_blank"` and `rel="noopener noreferrer"`.

## Validation

- Loader tests cover artifact availability for stats and missing tearsheet.
- Server tests cover account curve route, HTML report route, and 404 for unsafe/missing tokens.
- Static UI tests cover rendering enabled/disabled buttons from run artifact metadata.
- Browser smoke should load the UI and verify the buttons appear for an existing run.
