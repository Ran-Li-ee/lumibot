## Bug Found During Validation

- Symptom:
  A prior completed rotation run showed same-day buy orders rejected after confirmed sells because `orders_submit_order` still saw stale cash. A later short-window run also exposed a first-iteration accounting issue where the first buy was filled but cash was not deducted before confirmation.
- Root cause:
  In backtesting, `broker.process_pending_orders()` can fill the order and enqueue a strategy executor event. The actual cash update for stock orders happens when the strategy executor processes that fill event. During the first trading iteration, the executor normally skips queued events to avoid startup/history events, so confirmation could observe filled orders before cash was synchronized.
- Fix:
  `orders_confirm_order` now flushes the strategy executor queue after processing pending backtest orders. During this confirmation-only flush, it temporarily clears first-iteration flags and restores them afterward, so current orders generated by the confirmation path are processed without changing Lumibot's main lifecycle state.
- Regression coverage:
  `tests/test_agent_tool_permissions.py` now covers stale cash after backtest pending-order processing and first-iteration confirmation flushing.
